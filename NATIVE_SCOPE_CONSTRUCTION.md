# Native scope derivation: current construction, 11 October 2026

**Status:** corrected native TLS entry capture and four conditional address-parametric VEX contracts pass after three unchanged complete Modal workflows. The contract permits a stated disjoint-object renaming relation and selected irrelevant state; it assumes stable valid ownership and does not enforce native runtime admission or prove ISA/fault/resource/adaptive equivalence. All four answers remain unknown. The earlier scalar cache fails complete-build usefulness. V27 remains the audited tape candidate; sharing remains disabled. All three independent V27 reviewers give Major revision and predate this construction. Naming the mechanism does not establish novelty.

The target invention is a checkable rule that derives which recipient differences a native computation region can safely ignore, while leaving native effects and response-dependent control live. A whole-backend successful tape is not the unit of admission. The native program may alternate between reusable certified regions and ordinary native execution, using actual recipient state at every re-entry.

## Rule and invariant

For a pinned native region `S`, a certificate describes `(code, entry, exits, P, D, W, T)`:

- `code`: executed instructions and reachable library bindings, not merely a source filename.
- `P`: checked entry preconditions covering ownership, aliases, effective options, stack/memory validity and admitted exceptional behavior.
- `D`: a complete transitive read projection, including response-derived state, addresses/provenance where relevant, global reads and control dependencies.
- `W`: the exact permitted live-out computation-state footprint, with a reconstruction relation for registers and owned memory. Recipient/kernel state is outside `W`.
- `T`: an independently checked transition relation for all admitted states, including exits and relevant faults. An unknown call, alias or effect prevents certification; observing no effect in one run is insufficient.

Before any shared lookup, validate the code binding and `P` at the real native entry. An invalid certificate or failed precondition executes `S` natively. The key is `(code, entry, certificate, D(actual_state))`; it is not the entire recipient context. A cached delta is usable only if its origin/transition is justified by the certificate and trusted deterministic production or by an independently checked transition witness. A MAC supplies integrity, not this justification.

The certificate must establish: for any two admitted entry states with equal `D`, native `S` chooses the same exit and related `W` transition, changes no recipient/kernel component, and performs no omitted permitted observation. Applying its checked delta must preserve the same native continuation. The relation includes the state native finish will read; copying a final object is not reconstruction.

Every allocation/free, native callback, stream operation, error path and other uncertified computation remains at its original native site. After an effect, the original continuation observes its actual return and all mutated state. Sharing resumes only at another certified entry; its `D` includes every actual response/state dependency unless the certificate proves independence. We do not substitute a producer warning count, stream error flag or successful return.

**Composition obligation:** induct on certified entries and native effect transitions. The entry relation and checked `T` preserve native computation state and the original continuation. The same native effect then produces related recipient state under a defended joint kernel/nondeterminism coupling. Re-establish `P` and derive the next projection from that actual state. This conditional argument is standard refinement reasoning; the proposed contribution is an enforced, useful derivation for actual native compiler regions, not the induction.

## Proposed delta and prior-art boundary

[Partial Memoization of Concurrency and Communication](https://www.cs.purdue.edu/homes/suresh/papers/icfp09.pdf) already stores constraints and resumes continuations. [R2](https://static.usenix.org/events/osdi08/tech/full_papers/guo/guo_html/index.html) already addresses interface cuts, callbacks, nondeterminism and unrecorded memory. [Riker](https://www.usenix.org/system/files/atc22-curtsinger.pdf) already tracks dependencies and replays build effects. [A Monadic Framework for Relational Verification](https://www.microsoft.com/en-us/research/wp-content/uploads/2018/04/2018cpp.pdf) already proves memoization using relational specifications. Merely implementing those techniques together would not establish substantial novelty.

The testable proposed delta is deriving, checking and enforcing a recipient equivalence class from the *transitive executed-code state footprint*, while preserving unwrapped native effect continuations and failures. It must soundly remove recipient constraints that an equally capable observed-constraint memoizer needs, admit useful real computation, and support the stronger native observation contract. It may overlap other work; the targeted sources do not establish priority or absence.

Industrial query systems are also relevant prior art. [rustc's query model](https://rustc-dev-guide.rust-lang.org/queries/query-evaluation-model-in-detail.html) memoizes pure providers; its [incremental backend discussion](https://rustc-dev-guide.rust-lang.org/queries/incremental-compilation-in-detail.html) explains that opaque LLVM C++ backend work is not automatically tracked by that query system. [Salsa](https://salsa-rs.github.io/salsa/reference/algorithm.html) tracks input/query dependencies and also supports [diagnostic accumulators](https://salsa-rs.github.io/salsa/tutorial/accumulators.html). Dependency-derived scope or retaining diagnostics is therefore insufficient novelty. The remaining hypothesis is useful checked native-state refinement for opaque compiler computation under the stronger recipient/failure contract; no reviewed source proves that hypothesis new.

The strongest baseline uses the same cutpoints, complete inputs, live native continuations, store budget, normal fill-on-miss behavior and observer policy. Compare its response/state equality constraints with certificate-derived nondependence. If the capable baseline obtains the same scope and costs without the proposed proof rule, explain the remaining assurance contribution or reject the claimed algorithmic novelty.

[MuCache](https://www.usenix.org/system/files/nsdi24-zhang-haoran.pdf) already supplies a cache correctness argument for dynamic service graphs using declared read-only endpoints and service assumptions. Native trace preservation or dependency tracking by itself is not a new contribution. A guarded native partial evaluator is also a necessary baseline: if a derived region always yields one answer under a cheap guard, returning that answer directly can dominate shared memoization.

### Finite native anchor and conditional address model

The [finite checker](scripts/check_rgec_native_transition.py) runs pinned ELF instructions with captured native objects/TLS and a private ABI model stack. Untouched registers and unavailable GS stay symbolic. Unknown addresses/control, outside-ELF calls, hooks, syscalls/dirty effects and writes outside private stack/KnownBits reject. No SimProcedure supplies a native library return. All four native-output, ABI-register, segment-base and return-stack checks pass. Each path has 114 blocks, 37 non-stack reads and 134 writes: 122 private-stack and 12 KnownBits write events.

The [conditional derivation](scripts/derive_rgec_native_contract.py), [Modal controller](modal_rgec_native_contract.py), and retained contract use eight logical objects: parent node, its type array, operand pair, child node, child type array, demanded APInt, output KnownBits and thread-canary bytes. Four actual pointer edges bind their graph. The shape and candidate variable fields are manually bounded choices checked against native execution; this is not arbitrary-program automatic inference.

| Contract component | Checked model treatment |
| --- | --- |
| Eight object locations, total 232 footprint bytes | Independent aligned canonical bases; pairwise disjoint and outside native code/private model stack |
| Four pointer edges | Values name the corresponding logical objects; aliases from repeated access remain consistent |
| Thirty-eight initial object bytes | Fixed to each captured template; includes actual opcode/type/demand/resno fields |
| Twenty-four immutable ELF bytes | Bound to the pinned read-only native program data |
| Prior output state | Arbitrary values/padding; equal APInt widths 1-64 avoid the unadmitted old-wide-value free |
| Other ignored state | Nonempty result counts, operand padding, stable canary, unused DAG argument and unavailable GS vary symbolically |
| Live-out | Zero=0, One=0, widths32; output offsets 12-15 and 28-31 preserve recipient padding |

For each native access, SMT must prove the computed logical address equals the declared object plus offset. Only then does the adapter replace that address with representative storage. It never adds a condition equating symbolic object bases with the captured numeric bases. Every native read/write PC and size must match its witness, every block remains pinned, and any additional feasible branch/exit rejects. This supplies the checked model address relation under the declared disjoint ownership domain, rather than raw-address canonicalization by assertion.

All four templates pass 182 explicit inequality checks each: 37 logical read addresses, 134 write addresses, two return/stack checks, eight preserved-register/segment checks and one output relation. Engine feasibility checks are additional. Written output offsets 0-11 and 16-27 equal native constants; the eight padding bytes equal their arbitrary initial recipient values. The stable TLS object remains unchanged. Private stack writes stay confined. Memory outside these write footprints is framed by the model's access checks.

**Conditional result:** within this VEX/solver model and the stated stable/readable/owned disjoint-object predicate, arbitrary supported object placement and the selected ignored values preserve the native path, ABI state and output relation. These are quantified symbolic variables in a model, not additional physical compiler experiments. Valid ownership, lifetimes, actual fault-free memory and the relation of VEX to native ISA remain assumptions/open connections. Overlapping/cyclic alias classes and resource/concurrency/failure behavior are not covered. No before-lookup runtime guard or cache implementation consumes this contract.

## Implemented scalar candidate, 11 October

[The native wrapper](src/unauthorized_channels/clang_knownbits_scope.cpp) constructs a structural projection before reading its bounded store. It accepts simple scalar integer types of 1–64 bits, demanded element `1`, and native recursion depths 0–6. Supported source cases are integer constants, the native depth cutoff, loads with no range metadata, zero-extending loads, AND/OR/XOR, and integer extension/truncation. Unsupported nodes, vector types, metadata analysis and target callbacks execute the original native computation. The 512-word bound rejects oversized projections; it does not truncate them into keys.

The projection includes node opcode, scalar width, result number, native depth, constant values, and load extension/memory width where the source reads them. It recursively includes the accepted operands. A non-null range metadata pointer rejects the ordinary load case before lookup. Pointer addresses, source names, diagnostics and recipient output paths are absent only because the accepted source branches do not consume them. This is a manually defined domain, not an automatic footprint derivation for arbitrary LLVM code.

For valid, readable, stable native DAGs, the captured source gives a conditional argument: equal projections produce equal Known.Zero/One by induction over the bounded expression. Constants precede the depth cutoff; the load branch either sets the high zero bits or returns unknown; bitwise operations combine both child results; extensions/truncation apply the captured scalar rules. The key retains the depth cutoff, so it does not replace conservative native analysis with a stronger analysis that could change instruction selection. Applying the result updates the actual caller's KnownBits object and resumes its original continuation; it does not replace backend output, diagnostics or native file operations.

That argument assumes the captured source describes the pinned native code and that input/output ownership, APInt lifetime, exceptional behavior and concurrent mutation satisfy its conditions. The ELF call-binding checker pins actual instruction bytes and original targets but does not discharge those assumptions. Neither a trusted native producer nor matching shadow answers proves all admitted machine transitions. The experimental packets are host-controlled same-binary records, readable by the instrumented compiler; they are not the protected production sharing or adversarial-store boundary.

The candidate uses ordinary structural memoization as its capable baseline. It also includes a direct evaluator over the same checked projection. A cache hit is therefore only a mechanism observation. Qualification requires complete real build/test controls and measured costs against direct evaluation, the native implementation, and guard-only native execution. Native code runs for every unsupported scope and for cold misses. Shadow qualification executes the original analysis even on hits and checks both stored and direct answers. The result of this finite check cannot be relabelled a native certificate or novelty proof.

The [Modal controller](modal_rgec_knownbits_scope.py) completed 19 unchanged zlib builds with upstream tests, 57 real repository-file round trips, and seven unchanged held-out libFuzzer C++ compilations. It separately counts driver plans. All finite recorded status/stream/artifact controls pass, with 64,525 actual native shadow-answer checks and zero disagreements. Original/cache-peer/direct median build child-plus-controller CPU is 4.71/4.85/4.77 seconds in three randomized order blocks on one worker. Peer caching loses to direct evaluation on CPU in all three blocks. These small correlated samples, and setup/producer/storage exclusions, do not establish a population speedup or amortized benefit. The initial harness failure passed driver arguments to the cc1-only executable; its raw diagnostics remain in `runs/rgec-modal-native-knownbits-scope-2026-10-11`. The corrected root is `runs/rgec-modal-native-knownbits-scope-2026-10-11-v2`; its independent audit is complete at 0/0 and verifies native bindings, 1,724 exported answers and retained controls/costs without additional compiler actions.

[LLVM's 2017 KnownBits-cache discussion](https://lists.llvm.org/pipermail/llvm-dev/2017-March/111431.html) already describes a real cache patch, measured compiler costs and outstanding flag invalidation errors. Caching this analysis, or adding invalidation hooks, is therefore not a defensible firstness claim. The implemented structural table is retained as a capable baseline. Do not expand its operator list or optimize its hit rate and relabel that exercise the primary invention. The next positive contribution must derive and check actual native equivalence, including mutation/ownership and effects, and demonstrate useful work that the equally scoped baselines do not already provide.

## Native and secrecy boundaries

The semantic obligation remains native diagnostics, authority, files, aliases, descriptors, errors, cleanup and future permitted tools. Exact metadata and variable crash output require an explicit joint relation, not deletion from raw evidence. An instruction-count profile cannot certify read footprints or absence of untaken effects.

CPU usage, resource ceilings, externally changed limits, concurrent observers and lookup/reconstruction failures need their own refinement. A fast region cannot silently survive a failure the native reference would encounter. Preallocation, fixed release times and hidden receipts are not sufficient arguments.

Adaptive cache-state noninterference is a separate composition: equal public/recipient histories must induce equal admission, reserved cold capacity, effect-release ordering, cancellation and visible failure transitions regardless of cache history. Recipient effects cannot escape before the allowed release. An unrestricted physical observer can detect omitted work through resource usage or contention; a software theorem must name and enforce its actual isolation boundary. We retain that obstacle rather than claiming universal physical secrecy.

## Decisive milestones

1. **Candidate selection on Modal.** Profile the pinned original compiler on unchanged real C/C++ translation units. Rank genuinely executed expensive regions and inspect their actual instruction/call footprints. Keep native versus profiled artifact/stream controls. Profiling selects work; it neither certifies it nor measures cache speedup.
2. **One code-bound certificate.** Implement a small checker for one actual region with complete reads, confined writes, native continuation and exceptional-path obligations. Validate every admitted input at entry independently of store contents. No synthetic callback or mock compiler substitutes for this step.
3. **Useful cross-context reuse.** Use separate producers and fresh recipients, genuine diagnostic histories/policies and actual native failing effects. Retain held descriptors, aliases and queued events; run native downstream tools and unchanged complete project tests. The region must execute sufficiently often and save more work than certification/lookup/reconstruction consume.
4. **Capable comparison and adaptive composition.** Compare the strongest compatible effectful cache with full costs, then implement the public admission/release/cold-capacity contract and challenge adaptive requests, saturation, eviction and cancellations. GPU/model work remains secondary.

Any admitted out-of-footprint read/write, changed native continuation/failure scope, unexplained stable future-observation difference or cache-history-dependent public transition falsifies the candidate. Admitting no useful work, or charging more complete work than it saves, fails the research goal even if the local certificate is sound. Passing finite workloads does not enlarge the certified domain.
