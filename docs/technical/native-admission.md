# Native admission contract — current research obligation, 9 October 2026

**Status:** a candidate admission rule and proof ledger. V22 has complete-workflow evidence; V23 changes function-reference representation; V26 repairs tested report routing and compiler lifecycle; V27 rejects tested file-size failure contexts before lookup. V26's audited fresh producer/recipient regression passes 432 finite native comparison pairs in 648 compiler calls. Neither this document nor the integrity receipt is a semantic certificate. Substantial novelty and adaptive noninterference remain unestablished. Start with [FINAL_HANDOFF.md](../HANDOFF.md) for verified results and current jobs.

The intended contribution is useful cross-context reuse with a checkable native refinement: preserve recipient-specific diagnostics, output authority, failure and future observations while sharing only the computation that does not depend on that context. The current scope comparison isolates that question from service placement and packet format. Its full-context baseline uses the same native prefix, private store and genuine packets, with one additional full-context equality guard. A scope miss executes the native backend and does not fill the seeded store. This is a controlled key-scope comparison, not the strongest general effectful-memoization baseline.

## The rule to justify

Write native state at the cutpoint as `(c, r, u)`: closed computation state `c`, recipient renderer state `r`, and recipient/kernel state `u`. A valid certificate must describe an executable effect program `p(c)` and establish the following for **every** admitted recipient state, not just the state of a successful producer:

`NativeBackend(c, r, u) ≈ NativeFinish(Interpret(p(c), r, u))`.

Here `≈` means the same permitted future observations of the recipient, including status, streams, files, aliases, held descriptors, errors and queued events. The current structural/event comparator is evidence for a weaker finite projection; it does not define or prove this contextual relation. Numerical metadata and fresh names need a joint native coupling or an enforced observer boundary.

For a straight-line effect tape, the certificate has four obligations:

1. **Closed computation.** Every value read by skipped native computation is determined by `c`, including effective options, selected pipeline, global state, external reads and module/value-name state. A successful intercepted map read covers that read only.
2. **Effect completeness.** Every visible effect of skipped computation appears in the program, or remains in an identical recipient-native prefix/finish. This includes independent sinks, direct stderr, flushes and native cleanup.
3. **Response closure.** For every operation, the remaining computation is independent of its recipient-specific response **and every state change the operation causes**, or a validated continuation follows the actual response. A fixed return value proves only the return-channel part. Return type `void` does not prove independence from stream position, error flags, callbacks, globals or later reads.
4. **Native interpretation.** Each operation uses the genuine recipient operation in the original order, with all fields it reads preserved. Generated-function snapshots require a separate argument; a parsed genuine module is not automatically interchangeable with the recipient's live module.

The supported-domain predicate and certificate must be determined from recipient/public state before shared lookup. Unknown code, reads, effects, response dependencies or unsupported options must choose native execution independently of cache contents. A producer trace, an operation-kind whitelist and a MAC cannot discharge these obligations.

**Conditional refinement argument:** relate the native and interpreted executions at the cutpoint. Closed computation gives the same next outgoing request and local computation transition. Native interpretation gives related recipient states and the actual recipient response. Response closure preserves the relation for the remaining skipped computation. Induction over effects, followed by native finish, gives the displayed contextual refinement. This argument is conditional and overlaps established effectful memoization; the research contribution must be an enforced useful native certificate, not the induction itself.

## Source-level stack renderer lemma

For the reported source revision, consider two valid `DiagnosticInfoStackSize` warning requests delivered to the same recipient-native handler state. If their function names, 64-bit stack sizes and 64-bit limits agree, changing the referenced LLVM function body/module does not change this handler's diagnostic action or its true return. This is a local source-level request equivalence, not a compiled-library certificate or skipped-backend theorem.

The [native stack branch](https://raw.githubusercontent.com/llvm/llvm-project/4021cee996f75e8f591991e53180d1d29dfd20d6/clang/lib/CodeGen/CodeGenAction.cpp) passes only the function name to recipient declaration lookup. On success it reports the genuine recipient declaration/location/context and the native uint32 truncation of stack size. On lookup failure, the dispatcher selects the warning diagnostic and calls the request's native printer at an invalid location. The [resource printer](https://raw.githubusercontent.com/llvm/llvm-project/4021cee996f75e8f591991e53180d1d29dfd20d6/llvm/lib/IR/DiagnosticInfo.cpp) uses resource name, size, limit and function; [printing that LLVM value](https://raw.githubusercontent.com/llvm/llvm-project/4021cee996f75e8f591991e53180d1d29dfd20d6/llvm/lib/IR/DiagnosticPrinter.cpp) reads its name alone. Resource name, kind and warning severity are fixed by the stack-request constructor. Neither branch reads the referenced LLVM function body. Recipient AST lookup and diagnostics remain live; they are not copied from the producer.

Thus both requests choose the same branch and diagnostic inputs in the same recipient state. The native entry then returns true. The fields carried by current kinds 5/6 preserve this tuple, including the limit used by the generic branch. This justifies investigating a smaller generated-function representation, but does not certify such an implementation. All observed limits remain zero. Allocation/fatal behavior, lookup side effects, LLVM filtering, binary/source equivalence, subsequent reads of mutated recipient state and native stream failures are separate obligations. The six exact primary-source byte snapshots and hashes are retained in `runs/rgec-stack-renderer-source-argument-2026-10-05-v22`.

## Source-level diagnostic query-state lemma

At the reported source revision, a normally constructed native `ClangDiagnosticHandler` has null inherited `DiagnosticContext` and `DiagHandlerCallback` fields. Its constructor stores the code-generation options and backend-consumer pointer in private members; it does not populate those inherited fields. The [native LLVM context getters](https://raw.githubusercontent.com/llvm/llvm-project/4021cee996f75e8f591991e53180d1d29dfd20d6/llvm/lib/IR/LLVMContext.cpp) return the inherited fields. Thus those two getters expose null values independently of the recipient's AST, diagnostic count or declaration map for this handler construction. This covers those getter results, not every possible way native code can access state.

The four virtual remark-enabled queries in [the native Clang handler](https://raw.githubusercontent.com/llvm/llvm-project/4021cee996f75e8f591991e53180d1d29dfd20d6/clang/lib/CodeGen/CodeGenAction.cpp) read only the effective code-generation remark patterns and, for the per-pass queries, the supplied pass name. Holding those inputs fixed and leaving those patterns unchanged gives the same query results across recipient diagnostic histories, assuming normal completion. The current residual bridge delegates these queries to that handler and initializes its own inherited context/callback fields to null. Its added recipe and snapshot bookkeeping does not enter these query expressions. Diagnostic delivery remains a distinct operation that may mutate recipient state.

These source-level facts close a few explicit query channels beyond the callback's fixed true return. They do **not** establish transitive response closure: `getDiagHandlerPtr` exposes a handler pointer; other callbacks, memory, allocation, shared streams and subsequent native reads still need an argument. The actual native library's retained undefined-symbol list includes imports of both inherited-field getters, so their existence must not be dismissed. The source/header bytes and fixed-return handler disassembly are retained in `runs/rgec-native-library-identity-2026-10-05-v21`, `runs/rgec-stack-renderer-source-argument-2026-10-05-v22` and `runs/rgec-native-library-interface-2026-10-05-v22-v2`. No complete binary/source equivalence or semantic certificate follows.

## V23 representation mechanism and local argument

The V23 kind-6 recorder invokes the genuine native `CloneModule` on the actual backend module. It retains the diagnosed function definition and every function directly used by a `BlockAddress`. Other functions, globals and aliases become native external references. The name, size, limit and original module identifier remain the request fields. This applies to both genuinely generated functions and original functions renamed by the actual native symbol-rewrite pass: kind 6 means absent from the captured prefix, not necessarily a newly created body. No C/C++ functions are appended to these workloads.

At the reported source revision, [CloneModule](https://raw.githubusercontent.com/llvm/llvm-project/4021cee996f75e8f591991e53180d1d29dfd20d6/llvm/lib/Transforms/Utils/CloneModule.cpp) creates mappings for original functions with the same names and attributes, then natively clones each selected definition. The selected diagnosed function therefore exists as a genuine definition in the snapshot and has the same name. Its block-address owners are retained conservatively because [native value mapping](https://raw.githubusercontent.com/llvm/llvm-project/4021cee996f75e8f591991e53180d1d29dfd20d6/llvm/lib/Transforms/Utils/ValueMapper.cpp) needs real mapped basic blocks. The stack size and limit are serialized without transformation. After successful native bitcode parsing, the earlier stack-renderer lemma supplies the same local diagnostic action for full and sliced references in the same recipient handler state.

This argument covers the renderer's field equivalence after successful snapshot creation/parsing. It does not prove allocation/fatal equivalence, complete snapshot validity for every native module, compiled-library equivalence, subsequent backend-state independence, cache admission or adaptive noninterference. Native verification of actual packets is finite evidence for parsing/validity. Keeping all block-address owners can preserve many unrelated real definitions; it is deliberately conservative and has measurable cost. The three exact cloning/mapping primary-source files are retained in `runs/rgec-stack-slice-source-argument-2026-10-05-v23`.

The genuine diagnostic-history experiment varies Clang's `-ferror-limit=1` versus `-ferror-limit=0` and recipient warning/error policy. This is distinct from the LLVM stack request's `StackLimit` field, which remains zero in all observed packets. Passing error-limit tests therefore supplies no evidence for nonzero `StackLimit` values.

## Native stream-state obligation identified on 8 October

The exact [stream interface](https://raw.githubusercontent.com/llvm/llvm-project/4021cee996f75e8f591991e53180d1d29dfd20d6/llvm/include/llvm/Support/raw_ostream.h) makes `tell` depend on both position and buffered bytes. Its nonvirtual `flush` acts on the receiving object's buffer. Current `RecordingStream` is unbuffered and delegates writes to a potentially buffered native stream; flushing the proxy therefore does not generally forward a native flush. Final object equality does not discharge that API difference.

The [native descriptor implementation](https://raw.githubusercontent.com/llvm/llvm-project/4021cee996f75e8f591991e53180d1d29dfd20d6/llvm/lib/Support/raw_ostream.cpp) advances logical position before attempting writes, retains errors for destruction, and implements pwrite with seek/write/restore. A position argument must cover buffer state, seek outcomes and error flags, not just the void write return. The next focused experiment should observe these genuine native operations and failures on actual project compilations before choosing a buffer/flush repair.

The buffer/flush difference remains a source-level obligation, with no observed flush-specific counterexample or implemented buffer repair. The real resource-failure study below exposes a separate native stack-state counterexample. The retained ELF writer source contains no explicit flush call; no such trigger is claimed for the completed workloads. Three exact primary-source snapshots and hashes are in `runs/rgec-native-stream-source-argument-2026-10-08-v26`. Complete compiled-library equivalence remains unproved.

## V27 file-size failure admission and local routing argument

The independently audited V26 stream study preserves 192 comparison executions, three genuine packet producers and 96 actual libc transcripts. All 72 returned output-call sequence comparisons match, including real ENOSPC/EFBIG returns. Yet all 24 file-size-failure replay/native pretty-stack-trace stage comparisons differ: `Per-function optimization` versus `Code generation`. Literal stderr also differs among repeated native runs. The stable stage difference is an explicit additional native observation; raw diagnostics are not rewritten or treated as wholly deterministic.

V27 inspects `RLIMIT_FSIZE` before LLVM initialization or cache query for protocol-bound cc1 requests. A finite soft limit, or failure to inspect it, emits the host-private native-route receipt and executes the pinned original compiler with the original cc1 arguments. Successful exec leaves the experimental tape, handlers and skipped backend out of that request's execution. The predicate does not inspect a key, packet, hit or store state. This establishes a local cache-independent routing argument conditional on the trusted compiler binding, successful exec and the protocol observation boundary. It is not the adaptive policy theorem; unknown limit inspection and exec failure have not been empirically exercised.

The genuine V27 run has 192 comparison executions plus three packet producers. All 24 native failure-stage comparisons now match, with 24 prequery private replays and 24 retained ordinary/device-failure hits. Status/object/limited structural/event projections match in all 144 native pairs. Only 72 literal status/stream pairs match; all raw file-size crash-stream differences remain. The audit verifies actual private receipts with no query/key, actual hit bindings, unchanged source bodies, compiler pins, 96 transcripts and traced/untraced/repetition controls. See `runs/rgec-modal-native-stream-admission-2026-10-09-v27/independent-stream-audit.json`.

A real file-size exclusion does not prove the remaining domain sound. General stream error/fatal paths, internal flush/tell, allocation, resource ceilings, direct effects and later recipient-state reads remain obligations. These component tests do not transfer V26's 648-call regression or V22's full-workflow costs to V27. Production shared reuse remains disabled.

## What would make the result substantial

The decisive result is an independently checkable supported native domain where computation scope soundly admits useful recipient-context differences, with an enforced rejection rule for everything outside that domain. It must survive real whole-project tasks and failure paths, show an advantage under an equally scoped baseline, and compose with an implemented adaptive observation contract. Narrowing a key, caching an IR hash, moving lookup into the cloud, or finding one released cache's permission mismatch is insufficient.

[Riker](https://www.usenix.org/system/files/atc22-curtsinger.pdf) already reasons about filesystem dependencies and effect replay. [Partial memoization of concurrency and communication](https://www.cs.purdue.edu/homes/suresh/papers/icfp09.pdf) already uses effectful constraints and saved continuations. [Predictive timing mitigation](https://askarov.net/ccs2011.pdf) already provides public scheduling and leakage arguments. The proposed native certificate and stronger observer contract need a precise comparison against those results; current experiments establish no priority over them.

**Additional primary-source check, 8 October:** [R2](https://static.usenix.org/events/osdi08/tech/full_papers/guo/guo_html/index.html), sections 2.2–2.5, already treats interposition cuts, isolation of unrecorded memory, nondeterminism, callbacks and allocation. It compares replay with recording and explicitly leaves recorded-versus-unwrapped equivalence outside that guarantee. RGEC must establish recipient refinement against unwrapped native execution and adaptive cache-state secrecy separately; describing a replay interface is insufficient. [Verified Secure Compilation for Mixed-Sensitivity Concurrent Programs](https://arxiv.org/abs/2010.14032) already separates semantic and security preservation in a mechanized refinement argument. Such a decomposition alone is not the novelty. This targeted search is not exhaustive and does not establish absence of prior work.

Next implementation work should close the ledger's dependency/response obligations. If a sound static boundary cannot be justified, preserve actual response-dependent native continuations rather than extending unconditional tapes on the strength of additional passing examples. Do not enable production shared reuse or rename the current receipt a certificate.
